# Source Ranking Rules

Use this file when selecting or citing A-Team references.

## Ranking order

1. Oracle product documentation or canonical product behavior, when available in the user's provided context.
2. A-Team blogs that directly match the integration pattern, Oracle product combination, or operational concern.
3. A-Team blogs that provide implementation examples or design cues for a similar pattern.
4. General examples or supporting blogs.

## Citation rules

- Cite only sources that materially influenced the design.
- Do not cite a source merely because it appears in the catalog.
- Prefer a small set of high-relevance references over a long bibliography.
- When multiple sources overlap, cite the most specific source and use the broader source only if it adds a distinct design principle.
- If guidance conflicts, state the conflict and prefer the more canonical, current, or scenario-specific source.

## Source metadata conventions

Each reference entry uses this shape:

- Type: a-team blog, oracle documentation, example, or supporting reference.
- Category: the design category where it belongs.
- Relevance: high, medium, or low.
- Authority: canonical, design guidance, example-only, or supporting.
- Freshness: stable or version-sensitive.
- Use when: when the source should influence the design.
- Do not use for: where the source should not be treated as authoritative.
