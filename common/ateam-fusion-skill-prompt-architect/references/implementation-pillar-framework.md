# Fusion Cloud Implementation Pillar Framework (Prompt Coverage Guide)

Use this guide to ensure prompts generated by `fusion-skill-prompt-architect` cover the full A-Team implementation span, not only data extraction.

Primary context reference:
- https://www.ateam-oracle.com/oracle-fusion-cloud-implementation-architecture-a-7-pillar-framework-for-scalable-and-ai-ready-deployments

## Pillar 1: Cross-pillar business architecture (HCM/ERP/SCM/CX)

- Define process boundaries and handoffs across pillars.
- Call out shared master-data dependencies and ownership.
- Capture impacts of one-pillar decisions on other pillars.

## Pillar 2: Application integration architecture

- Specify integration patterns (API, event, batch, file, orchestration).
- Define source/target systems and contract boundaries.
- Include error handling, retries, and idempotency expectations.

## Pillar 3: Governance and operating model

- Define accountable owners (architecture, data, security, operations).
- Include approval gates and change-management controls.
- Specify release-readiness and operational sign-off criteria.

## Pillar 4: Data definition and lifecycle architecture

- Define canonical entities, quality expectations, and lineage.
- Capture data contract expectations (schema, semantics, SLAs).
- Include retention, archival, and reconciliation controls.

## Pillar 5: Security and compliance architecture

- Define IAM approach, least privilege, and role boundaries.
- Include data protection controls (masking, encryption, auditability).
- Capture SoD/compliance constraints and evidence requirements.

## Pillar 6: Extensibility architecture

- Distinguish upgrade-safe extension patterns from risky customization.
- Define event/model extension points and deployment boundaries.
- Include lifecycle controls for extensions and rollback behavior.

## Pillar 7: Monitoring and observability architecture

- Define telemetry model (functional, technical, business KPIs).
- Specify alerting thresholds, ownership, and escalation routes.
- Include run diagnostics and post-incident feedback loops.

## Prompt acceptance requirement

A prompt is considered implementation-complete only when all seven pillars are:

1. Explicitly mentioned,
2. Mapped to concrete actions/controls,
3. Linked to measurable acceptance criteria.
